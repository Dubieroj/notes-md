## 0. Как читать документ

**Идентификаторы.** У каждого требования есть код: `UI` (интерфейс), `ED` (редактор), `ORG` (организация), `CORE` (основные функции), `STO` (хранение), `MAC` (возможности macOS), `TECH` (стек), `PRO` (уникальные функции Пера), `PERF` (производительность), `SEC` (безопасность), `PAR` (функции Notes, которых нет в исходных требованиях). Риски и противоречия обозначены `R1`…`R21`, открытые вопросы `В1`…`В14`.

**Приоритеты.**

| Код | Значение |
|---|---|
| P0 | MVP. Без этого Перо не заменяет Notes в повседневных сценариях |
| P1 | Паритет с Notes. Входит в «полный паритет» |
| P2 | Сверх Notes: раздел 8 требований и другие пункты, которых в Notes нет. Делается после паритета и только если подтверждено (см. R1) |
| P3 | Позже или под вопросом: высокий риск, зависимость от решения или от другой платформы |

**Эталон.** Под «как в Notes» понимается Notes на эталонной версии macOS (см. 1.4). Где точное поведение Notes не проверено, стоит пометка «сверить с эталоном»: такое место перед реализацией проверяется на живом Notes.

**Критерии приёмки** записаны как проверяемые утверждения. Всё, что можно, проверяется автоматически, развитием текущего `tools/check.sh` (см. 5.11).

**Эталонный Mac** для измерений — Mac автора: MacBook Air M1 (2020), 8 ГБ памяти, Touch ID, macOS 15.7.7.

## 1. Концепция

### 1.1 Одной фразой

Перо — это «Заметки» для Mac, в которых каждая заметка является обычным `.md`-файлом. Выглядит и ведёт себя как Notes, а данные можно открыть любым редактором, положить в git и прочитать через двадцать лет.

### 1.2 Для кого

Пользователи Mac, которым нравится простота Notes, но нужны переносимость, совместимость с git и простой текст. Первый пользователь — автор: интерфейс на русском, MacBook Air M1, macOS 15.

### 1.3 Принципы

1. **Markdown — источник истины.** Файл заметки — ровно то, что видно в режиме исходника. Никакой скрытой служебной разметки и никакого front matter, добавленного без спроса. Нетронутые места файла сохраняются байт в байт: кодировка, BOM, переводы строк (это уже умеет текущее Перо).
2. **Файлы принадлежат пользователю.** Библиотека — обычные папки с `.md`-файлами. База SQLite — только индекс: её можно удалить, и она пересоберётся.
3. **Поведение как в Notes.** Если функция есть в Notes, Перо повторяет её место в интерфейсе, клавиши и контекстные меню. Отступать можно, только если Markdown не выражает то же самое (см. 1.5). Каждое отступление записывается.
4. **Офлайн и приватно.** Из приложения не уходит ни одного сетевого запроса, и это гарантирует сама система (песочница без сетевых прав, SEC-04).
5. **Сверх Notes — только по решению.** Всё, чего нет в Notes, помечено P2 и требует подтверждения (R1). Исключение — то, что уже умеет текущее Перо.

### 1.4 Эталон паритета

Notes меняется каждый год, поэтому «полный паритет» нужно привязать к версии.

| macOS | Что нового в Notes, важное для Пера |
|---|---|
| 15 Sequoia (у автора 15.7.7, Notes 4.11) | Запись аудио с расшифровкой, выделение текста цветом (5 цветов), сворачиваемые разделы под заголовками, Math Notes (вычисления после «=»), Writing Tools (с Apple Intelligence) |
| 26 Tahoe | Импорт и экспорт Markdown (через меню «Файл»), элемент «Быстрая заметка» в Пункте управления, Liquid Glass |
| 27 (вышла 14 сентября 2026, Notes 4.13) | Рисование трекпадом прямо на Mac, разделитель (⌘L), ссылки на раздел заметки, «Скопировать как Markdown» |

**Предложение.** Эталон — Notes на macOS 15, которой автор пользуется сейчас. Функции 26 и 27 вынесены в список `PAR`, по каждой своё решение. Эталон пересматривается раз в год, после выхода новой macOS. M1 поддерживается и macOS 26, и macOS 27, так что при обновлении автора эталон стоит сдвинуть.

Важно для позиционирования: начиная с macOS 26 Notes сама умеет импортировать и экспортировать Markdown. Отличие Пера в том, что Markdown у него — формат хранения, а не формат экспорта: файлы живые, их можно держать в git, править внешними редакторами и читать без Пера.

**Исключено намеренно** (по требованиям и по смыслу локального приложения): синхронизация через iCloud, совместная работа, общие заметки и папки, упоминания (@), список активности, уведомления об общих заметках, несколько учётных записей (iCloud, «На Mac», Gmail). В Пере одна локальная библиотека.

### 1.5 Как форматирование Notes ложится на Markdown

| В Notes | В файле Пера | Комментарий |
|---|---|---|
| Название (Title), первая строка | `# Текст` | Первая непустая строка — название заметки, даже без `#` (ED-02) |
| Заголовок (Heading) | `## Текст` | |
| Подзаголовок (Subheading) | `### Текст` | Уровни 4–6 есть только в Пере (`####`…`######`) |
| Основной текст (Body) | обычный абзац | |
| Моноширинный (Monostyled) | блок ```` ``` ```` или `` `код` `` | Для целых абзацев — блок, для слов внутри строки — инлайн-код |
| Маркированный список | `- пункт` или `* пункт` | Показывается «•» |
| Список с тире | `+ пункт` | Решение Пера: маркер `+` (допустим в CommonMark) показывается «–». Другие редакторы покажут обычный список |
| Нумерованный список | `1. пункт` | |
| Чек-лист | `- [ ] пункт`, `- [x] пункт` | |
| Цитата | `> текст` | |
| Жирный, курсив, зачёркнутый | `**…**`, `*…*`, `~~…~~` | |
| Подчёркнутый | `<u>…</u>` | HTML-тег, его показывают GitHub и большинство редакторов |
| Выделение цветом | `==…==` | Один цвет. Пять цветов Notes Markdown не выражает (R10) |
| Ссылка | `[текст](адрес)`, голый адрес | |
| Ссылка на заметку | `[[Название]]` | Вставляется и через `>>`, как в Notes (PRO-04) |
| Ссылка на раздел | `[[Название#Раздел]]` | |
| Тег | `#тег` в тексте | |
| Таблица | таблица GFM | Перенос строки внутри ячейки — `<br>`. Объединённых ячеек нет ни там, ни там |
| Разделитель | `---` | |
| Картинка | `![подпись](Attachments/…)` | С заданным размером — `<img src="…" width="320" alt="…">` |
| PDF, документ | `[Отчёт.pdf](Attachments/…)` | Перо показывает карточку или встроенный просмотр |
| Скан | PDF во вложениях и ссылка на него | Текст скана распознаётся для поиска, но в файл не пишется |
| Рисунок | `![Рисунок](Attachments/….svg)` | SVG с данными штрихов внутри |
| Аудиозапись | ссылка на `.m4a` и расшифровка текстом под ней | P3 |
| Шрифт, цвет, размер текста | — | Не переносится, в Markdown этого нет. При импорте теряется и попадает в отчёт (R10) |
| Свёрнутый раздел | — | Состояние хранится в индексе, не в файле |
| Результат Math Notes | обычный текст после `=` | P3 |

### 1.6 Метрика успеха в проверяемом виде

Формула «пользователь, перешедший с Notes, ничего не теряет» считается выполненной, когда:

1. каждый пункт чек-листа паритета (Приложение Б) со статусом «входит» прошёл приёмку;
2. все отступления из 1.5 и R10 перечислены и автор их принял;
3. пилот: автор импортировал свои заметки из Notes и две недели работал только в Пере. Каждый случай, когда пришлось открыть Notes, записан и закрыт исправлением или принятым отступлением.

## 2. Что уже есть в проекте

Проект: этот репозиторий. Сейчас Перо — документный редактор Markdown: класс документа `MarkdownDocument` (`NSDocument`), одно окно на файл, вкладки, боковая панель с деревом папки и оглавлением. Редактор — CodeMirror 6 в `WKWebView`. Кода около 1 200 строк на Swift и около 1 000 строк на JavaScript. Сборка: SwiftPM (`Package.swift`, минимальная macOS 13) и скрипт `run.sh`, который вручную собирает `build/Перо.app` и подписывает его. Git-репозитория у проекта нет. Установленная копия — `/Applications/Перо.app`, bundle id `local.pero.markdown`, назначена приложением по умолчанию для `.md`.

### 2.2 Что нельзя потерять

- Сохранение без порчи разметки: байт в байт, кодировка, BOM, CRLF. Сейчас это проверяет `tools/check.sh`, проверка остаётся в приёмке.
- Живое оформление со скрытой разметкой и показом разметки у элемента под курсором.
- Живое обновление файла, который дописывает другая программа (например, программа расшифровки речи).
- Работа офлайн, без сети и без аккаунтов.

### 2.3 Что меняется принципиально

1. **Документное приложение превращается в библиотеку**, как Notes или «Фото»: одно главное окно с папками, списком и редактором. Файлы не открываются и не сохраняются вручную.
2. **Окно на файл с вкладками** уступает трём колонкам. Отдельное окно заметки открывается двойным щелчком, как в Notes.
3. **Сохранение через `NSDocument`** заменяется автосохранением в ядре хранилища и индексом SQLite.
4. **SwiftPM** заменяется проектом Xcode с несколькими таргетами.
5. **Редактор** переходит с `WKWebView` (CodeMirror) на TextKit 2 через общий протокол. Порядок перехода — в 5.6 и R14.
6. **Минимальная система** поднимается с macOS 13 до macOS 15 (TECH-02).

### 2.4 Внешние `.md`-файлы

Перо назначено приложением по умолчанию для `.md`. Двойной щелчок по `.md` вне библиотеки открывает файл как сейчас: в отдельном окне-редакторе, правки пишутся в этот же файл, чужие изменения подхватываются на лету. В окне есть кнопка «Добавить в заметки»: файл и его картинки копируются в библиотеку. В Notes такого режима нет. Это не новая функция, а сохранение того, что Перо уже умеет (вопрос В5).

Оговорка про песочницу (SEC-04): система даёт приложению доступ только к открытому файлу. Картинки, лежащие рядом с внешним `.md`, будут видны после того, как пользователь один раз разрешит доступ к папке; разрешение запоминается закладкой.

### R2. Формата «.notes» для импорта не существует

Notes хранит все заметки в одной базе `~/Library/Group Containers/group.com.apple.notes/NoteStore.sqlite` (на Маке автора она есть). Тело заметки — сжатый gzip protobuf по недокументированной схеме, вложения лежат в отдельных папках, заблокированные заметки зашифрованы. Файла «.notes» нет. Реальные пути импорта:

| Путь | Что получим | Ограничения | Предложение |
|---|---|---|---|
| А. Notes сама экспортирует Markdown, Перо импортирует папку | Текст, структура папок, картинки во вложениях | Нужна macOS 26 или новее; у автора 15.7, придётся обновиться | P0: импорт папки Markdown нужен в любом случае |
| Б. AppleScript (Apple Events) к Notes | Название, тело в HTML, даты создания и изменения, папки | Разрешение «Автоматизация». По отчётам на форумах вложения сохраняются скриптом ненадёжно, состояние чек-листов может теряться — проверить в спайке. Заблокированные заметки — только после разблокировки. В песочнице нужно временное исключение для Apple Events (Mac App Store такое обычно не пропускает) | P0 для macOS 15: текст, структура, даты. Вложения — насколько получится |
| В. Прямое чтение `NoteStore.sqlite` | Максимум: чек-листы с состоянием, таблицы, вложения, сканы | Нужен «Полный доступ к диску». Формат недокументирован и меняется между версиями macOS; таблицы — CRDT внутри protobuf. Есть открытые разборщики (например, apple_cloud_notes_parser), но поддерживать это придётся всегда | P3, только если А и Б не хватит |

**Решить (В2):** обновлять ли macOS до 26/27 ради пути А.

### R3. «SQLite с обёрткой Core Data» против «файлы + SQLite для метаданных» и против переносимости

Если тела заметок лежат в SQLite, тем более через Core Data с её закрытой схемой таблиц `Z…`, то git, внешние редакторы и «простой текст на будущее» перестают работать, и главный смысл Пера теряется. Раздел 7 требований сам предлагает «File system + SQLite for metadata».

**Предложение.** Источник истины — файлы `.md` и небольшой `state.json`. SQLite — только индекс и кэш: полнотекстовый поиск FTS5, списки, ссылки. Индекс удаляется и пересобирается. Core Data не используется: она рассчитана владеть данными, а здесь владелец — файловая система. Используется системная `libsqlite3` (FTS5 в ней есть: проверено на Маке автора, SQLite 3.43.2) и тонкая обёртка на Swift, без внешних зависимостей.

**Решить (В3):** согласиться (рекомендую) или объяснить, зачем нужна Core Data.

### R4. Handoff без синхронизации

Handoff передаёт текущее действие (`NSUserActivity`) приложению с тем же Team ID на другом устройстве. Для этого нужны iOS-версия Пера, которой нет и которой нет в требованиях, и сама заметка на iPhone, которой там без синхронизации не будет. Текст можно передать вместе с действием или потоком (continuation streams), но это уже разовая синхронизация. Handoff с Mac в Safari на iPhone работает только для веб-адреса, а веб-версии у Пера нет.

**Предложение.** Handoff исключить (P3, только вместе с iOS-версией). Вместо него — «Отправить на iPhone» через AirDrop (файл `.md` или PDF, CORE-08). Универсальный буфер обмена работает и так.

**Решить (В4).**

### R5. Apple Pencil на Mac

Ни один Mac не поддерживает Apple Pencil. Холст PencilKit (`PKCanvasView`) есть на iOS, iPadOS и в Mac Catalyst, но не в AppKit. Рисовать в Notes на самом Mac стало можно только в macOS 27, трекпадом. Варианты для Пера:

- **Continuity Sketch:** «Вставить с iPhone или iPad → Добавить рисунок». Рисунок, сделанный на iPad, в том числе Pencil, приходит картинкой, редактировать его потом нельзя. Механизм тот же, что у сканирования (R6).
- **Свой холст в AppKit:** мышь и трекпад. Давление можно получить через Sidecar, когда iPad работает вторым экраном и Pencil ведёт себя как графический планшет.
- **Перо для iPad** — за рамками требований.

**Предложение.** Continuity Sketch — P1, свой холст — P3, рисунки хранятся в SVG.

**Решить (В6):** нужен ли собственный холст вообще.

### R6. Сканирование документов через Continuity Camera

Работает, но с условиями. Нужен iPhone или iPad рядом, с той же учётной записью Apple, Bluetooth и Wi‑Fi. В приложении нужен пункт меню с идентификатором `NSMenuItem.importFromDeviceIdentifier` и обработчик в цепочке респондеров: `validRequestor(forSendType:returnType:)` и `NSServicesMenuRequestor.readSelection(from:)`.

`NSTextView` поддерживает это автоматически, `WKWebView` — нет. Пока редактор на CodeMirror, данные придётся принимать на нативной стороне и передавать в страницу. `NSTextView` вставит полученное как вложение прямо в текст; это нужно перехватить и превратить в файл во вложениях плюс Markdown-ссылку. Текст сканов распознаётся на устройстве через Vision (поддержку русского проверить по `supportedRecognitionLanguages`).

**Предложение.** P1, этап 3. С TextKit 2 обходится дешевле.

### R7. Face ID на Mac нет, Touch ID есть не везде

Face ID на Mac не существует. Touch ID есть на MacBook с датчиком (у автора есть) и на Magic Keyboard с Touch ID; на Mac mini или Mac Studio без такой клавиатуры остаётся пароль. Ещё возможна разблокировка часами Apple Watch.

**Предложение.** Формулировка «Touch ID или пароль», Face ID из требований убрать.

### R8. Быстрая заметка: Fn‑Q и горячий угол заняты Notes

Системное сочетание Fn/🌐‑Q и горячий угол «Быстрая заметка» открывают только Notes, переназначить их на стороннее приложение нельзя. На macOS 26 и новее можно добавить свой элемент в Пункт управления (ControlWidget).

**Предложение.** Своё глобальное сочетание, настраиваемое (кандидат по умолчанию ⌃⌥⌘N, проверить конфликты). Плюс пункт меню «Службы» и вариант «В быструю заметку» в расширении «Поделиться». Сочетание работает, только пока Перо запущено, поэтому нужна настройка «Запускать при входе в систему».

### R9. «Анимации и вид идентичны Notes» — непроверяемая формулировка

Код и ресурсы Notes закрыты. Совпадения можно добиться, только используя те же стандартные компоненты AppKit (`NSSplitViewController`, списки, `NSCollectionView`): они дают те же системные анимации. Собственные анимации Notes (например, перестановка отмеченных пунктов чек-листа) повторяются на глаз. К тому же внешний вид меняется с каждой macOS (Liquid Glass в 26 и 27).

**Предложение.** Критерий — сравнение бок о бок на одной системе по списку экранов (скриншоты и видео). Дефект — расхождение, которое человек замечает за 5 секунд.

### R10. Чего Markdown не умеет из rich text Notes

Шрифты, цвета и размеры текста; пять цветов выделения; подчёркивание (только HTML `<u>`); размер картинки (только HTML `<img width>`); многострочные ячейки таблиц (только `<br>`); состояние свёрнутых разделов; рисунки и аудио как редактируемые объекты. Требование «ничего не потерять» здесь прямо противоречит требованию «только Markdown».

**Предложение.** Правила из 1.5: где можно, используется HTML-вставка, которую понимает GitHub; где нельзя, это явная потеря, которая показывается в отчёте импорта.

**Решить (В7):** допустимы ли HTML-теги в заметках (`<u>`, `<img>`, `<br>`) или нужен строго «чистый» Markdown.

### R11. «Ни одного сетевого запроса» против функций, которым нужна сеть

Картинки по `http`-ссылкам внутри заметок, превью веб-ссылок и карты (в Notes есть), курсы валют в Math Notes, Writing Tools и Apple Intelligence (часть запросов уходит в Private Cloud Compute) — всё это сеть.

**Предложение.** Удалённые картинки не загружаются; вместо них плашка с адресом, без кнопки «Загрузить». Превью ссылок нет, показывается адрес. Writing Tools — системная функция, решение за автором (В8): оставить или отключить через `writingToolsBehavior = .none`. Русский Apple Intelligence на момент написания не поддерживает, это стоит перепроверить. Резервная копия в iCloud Drive — просто запись в папку; в сеть ходит система, а не Перо.

### R12. Песочница, расширения и путь `~/Library/Application Support/Pero`

Расширения (Quick Look, «Поделиться», виджеты) обязаны работать в песочнице и не видят папку приложения. Общие данные доступны им только через контейнер App Group (`~/Library/Group Containers/<TEAMID>.…`). Если в песочнице и само приложение (рекомендуется, SEC-04), то «Application Support/Pero» физически окажется в `~/Library/Containers/local.pero.markdown/Data/Library/Application Support/Pero`.

Для нотаризации и раздачи другим людям нужен платный Apple Developer Program. У автора — бесплатная персональная команда разработчика. Проверено при сборке: с ней подписываются приложение и расширения, App Group `<команда>.local.pero` разрешена — для работы на своём Маке этого достаточно.

**Предложение.** Библиотека по умолчанию лежит в контейнере приложения, пользователь может выбрать свою папку (например, `~/Documents/Перо` для git). Расширения общаются с приложением через App Group: входящие от «Поделиться», снимок данных для виджетов. Писать в библиотеку может только само приложение.

### R13. Notes — движущаяся цель

См. 1.4. **Предложение.** Зафиксировать эталон и пересматривать его раз в год.

### R14. Редактор: TextKit 2 против готового CodeMirror

Нынешний редактор (CodeMirror 6 в `WKWebView`) уже решает самое трудное: скрывает разметку, рисует таблицы и чекбоксы, разбирает текст инкрементально, прокручивает большие документы без тормозов. Требования допускают «custom built or TextKit 2», а для «нативности» нужен TextKit 2.

Подводные камни TextKit 2:
- таблицы `NSTextTable` переключают `NSTextView` обратно на TextKit 1 (по словам инженера Apple на форумах разработчиков, это последний такой случай), поэтому таблицы придётся рисовать самим;
- скрытие разметки без изменения текста — набор приёмов (атрибуты, собственные фрагменты раскладки), а не штатная функция;
- VoiceOver будет зачитывать скрытые `**`, если не сделать отдельное представление для доступности.

Минусы `WKWebView`: отдельный процесс WebContent (память, холодный старт); выделение, доступность, Writing Tools и Continuity Camera работают не как в родных полях ввода.

**Предложение.** Редактор прячется за протоколом `EditorEngine`. MVP делается на текущем CodeMirror, параллельно идёт спайк TextKit 2 с измеримыми условиями (5.6.4). Переход — когда TextKit 2 проходит тот же приёмочный набор.

**Решить (В9):** обязателен ли TextKit 2 к релизу или CodeMirror допустим и дальше, если проходит приёмку.

### R15. Производительность с `WKWebView`

Холодный запуск быстрее 1 секунды с `WKWebView` реален, но впритык: процесс WebContent стартует отдельно. **Предложение.** Создавать веб-вид параллельно с чтением индекса и измерять время запуска с первого дня (PERF-01).

### R16. Заблокированные заметки и «простой текст навсегда»

Зашифрованная заметка уже не Markdown: её не откроет другой редактор, git видит бинарный блоб, забытый пароль означает потерю данных (в Notes так же). Если заметка раньше лежала открытой в git или в резервной копии, она там и останется.

**Предложение.** Формат-конверт с опубликованным описанием (SEC-02) и предупреждение при блокировке.

### R17. Название — первая строка, а имя файла?

В Notes название — первая строка заметки. Если имя файла следует за названием, каждая правка первой строки переименовывает файл: шум в git, ломаются внешние ссылки на файл. Если не следует, в Finder и git файлы называются не так, как заметки.

**Предложение.** Имя файла равно названию; переименование откладывается до паузы во вводе и ухода из заметки; ссылки `[[Старое название]]` обновляются автоматически.

**Решить (В10).**

### R18. Даты создания и закрепления вне текста

В «чистом» Markdown нет места для даты создания, закрепления и цвета тегов. Дата создания берётся из файловой системы, а `git clone` и копирование на другой диск её сбрасывают. Закрепления и смарт-папки хранятся в `.pero/state.json`.

**Предложение.** Принять. Front matter Перо не добавляет, но читает, если он уже есть (например, после импорта из Obsidian).

### R19. [[Вики-ссылки]] — не стандарт Markdown

GitHub и большинство просмотрщиков покажут `[[Название]]` как обычный текст. **Предложение.** При экспорте есть опция «превратить вики-ссылки в обычные `[Название](Название.md)`».

### R20. Аудио с расшифровкой и Math Notes есть в Notes, но не упомянуты в требованиях

По главному принципу («каждая функция Notes») они обязательны. Расшифровка на устройстве делается через Speech framework (или SpeechAnalyzer на macOS 26+); поддержку русского на устройстве нужно проверить. **Предложение.** P3, после остального паритета. **Решить (В11).**

### R21. Открытый исходный код

Нужна лицензия. CodeMirror и markdown-it распространяются под MIT и совместимы с любой. Для публикации bundle id `local.pero.markdown` лучше заменить доменом автора, но это сбросит назначение Пера приложением по умолчанию для `.md`; менять стоит один раз, до публикации. **Решить (В12):** MIT или GPLv3, когда публиковать.

## 4. Функциональные требования

Разделы 4.1–4.10 соответствуют разделам 1–10 исходных требований. Раздел 4.11 — функции Notes, которых в требованиях нет, но которые нужны по главному принципу.

### 4.1 Интерфейс и UX (раздел 1 требований)

**UI-01. Главное окно из трёх колонок · P0**

Боковая панель (папки, смарт-папки, теги), список заметок, редактор. Основа — `NSSplitViewController`.

Приёмка:
- ⌃⌘S скрывает и показывает боковую панель с системной анимацией.
- Ширины колонок, свёрнутость панели и размер окна восстанавливаются после перезапуска.
- При сужении окна колонки скрываются в том же порядке, что в Notes (сверить с эталоном).
- ⌘0 показывает главное окно, если оно закрыто.

**UI-02. Боковая панель · P0**

Разделы: «Быстрые заметки», «Заметки» (корень библиотеки, папка по умолчанию), папки пользователя с вложенностью, смарт-папки, «Недавно удалённые» (видна, только если не пуста), блок «Теги».

Приёмка:
- У каждой папки счётчик заметок, он обновляется сразу после изменений.
- Вложенность папок любой глубины; раскрытые папки запоминаются.
- Папка, перетащенная на другую папку, становится вложенной.
- Переименование по двойному щелчку и из контекстного меню; пустое имя и символы `/` и `:` не принимаются, показывается объяснение.
- Удаление папки отправляет её заметки в «Недавно удалённые», с подтверждением.

**UI-03. Список заметок · P0**

Строка списка: название жирным, дата и начало текста, миниатюра первой картинки справа, значки «закреплена» и «заблокирована». В «Заметках», поиске и смарт-папках показывается ещё и имя папки. Разделы «Закреплённые» и «Заметки», группировка по датам (ORG-07).

Приёмка:
- ↑/↓ выбирают заметку, ↩ переводит в редактор, Tab переключает боковую панель, список и поле поиска (как в Notes).
- Несколько заметок выбираются ⌘- и ⇧-щелчком; в редакторе тогда показывается число выбранных (сверить с эталоном).
- Правка заметки при сортировке по дате изменения поднимает её наверх без скачка выделения.
- У заблокированной заметки видно название, а вместо начала текста — «Заблокировано».
- 10 000 заметок прокручиваются без рывков (PERF-06).

**UI-04. Светлая и тёмная тема · P0**

Тема следует системной настройке и меняется на лету.

Приёмка:
- Смена темы в Системных настройках перекрашивает все колонки и текст заметки без перезапуска и без белой вспышки (в текущем Пере это уже решено: `drawsBackground = false`).
- Контраст основного текста не ниже 4,5:1 (WCAG AA) в обеих темах.
- Цвет акцента и выделения берётся из системных настроек, как в Notes.

**UI-05. Анимации и поведение как в Notes · P1**

Только стандартные компоненты AppKit и SwiftUI, без самодельных аналогов (R9). Сверяются: показ и скрытие боковой панели, переключение «Список/Галерея», закрепление (строка переезжает в «Закреплённые»), удаление, перестановка пунктов чек-листа, появление результатов поиска.

Приёмка: по каждому переходу — видео бок о бок с Notes на одной системе; расхождение, заметное за 5 секунд, считается дефектом.

**UI-06. Перетаскивание · P0 для заметок и файлов, P1 для остального**

- Заметка на папку — перемещение; на «Недавно удалённые» — удаление; в Finder или на рабочий стол — экспорт `.md` с вложениями; в другое приложение — текст Markdown.
- Между разделами «Закреплённые» и «Заметки» — закрепление и открепление (как в Notes).
- Папка на папку — вложение; в корень — на верхний уровень.
- Файлы `.md`, `.txt`, `.rtf`, `.html`, `.enex` на боковую панель или список — импорт (CORE-11).
- Картинки, PDF, документы в редактор — вложение в точку броска (CORE-03).
- Внутри редактора — перенос текста и вложений.

Приёмка: каждое действие отменяется ⌘Z; бросок в недопустимое место показывает запрещающий курсор.

**UI-07. Контекстные меню · P0 базовые, P1 полные**

- Заметка: Закрепить/Открепить, Заблокировать/Снять защиту, Переместить в ▸, Дублировать, Открыть в новом окне, Поделиться ▸, Экспортировать ▸, Удалить.
- Папка: Новая папка, Переименовать, Сортировать ▸, Группировать по дате ▸, Преобразовать в смарт-папку, Экспортировать, Показать в Finder, Удалить.
- Смарт-папка: Изменить фильтры, Переименовать, Удалить.
- Тег: Переименовать во всех заметках, Удалить тег, Цвет ▸ (P2).
- Текст: системные пункты (вырезать, скопировать, вставить, правописание, «Службы», «Перевести», «Найти») плюс Формат ▸, Ссылка…, Вложения ▸.
- Вложение: Быстрый просмотр, Открыть в ▸, Сохранить как…, Переименовать, Повернуть, Разметка, Показать в Finder, Размер ▸, Удалить.

Приёмка: состав и порядок пунктов совпадает с эталоном, кроме исключённых функций (общий доступ, упоминания); каждая команда доступна и из главного меню.

**UI-08. Отдельное окно заметки · P1**

Двойной щелчок по заметке открывает её в своём окне.

Приёмка: правка в отдельном окне сразу видна в главном и наоборот (общий буфер); закрытие окна ничего не теряет.

**UI-09. Масштаб содержимого · P1**

⇧⌘. и ⇧⌘, увеличивают и уменьшают текст заметки, ⇧⌘0 возвращает размер; размер текста по умолчанию задаётся в настройках. ⌘+ и ⌘− в Notes меняют размер шрифта выделенного текста; в Markdown размера шрифта нет, поэтому в Пере они работают как масштаб (R10).

Приёмка: масштаб меняется ступенями и держится до сброса ⇧⌘0; файл заметки при этом не меняется.

**UI-10. Настройки (⌘,) · P0 основные, P1 все**

Из Notes: «Сортировать заметки по», «Новые заметки начинаются с» (Название/Заголовок/Подзаголовок/Основной текст → `#`/`##`/`###`/абзац), «Группировать заметки по дате», «Всегда продолжать последнюю быструю заметку», «Автоматически сортировать отмеченные пункты», «Размер текста по умолчанию», «Заблокированные заметки» (пароль для входа в Mac или свой; сменить; сбросить; Touch ID).
Не нужны: учётная запись по умолчанию, уведомления об упоминаниях, учётная запись «На Mac».
Только в Пере: папка библиотеки (STO-08), резервное копирование (STO-04), режим редактора по умолчанию, сочетание для быстрой заметки, значок в Dock (P2), Writing Tools (R11).

Приёмка: каждая настройка применяется сразу, без перезапуска, и сохраняется между запусками.

**UI-11. Язык интерфейса · P0**

Интерфейс на русском, как сейчас. Строки собраны в String Catalog, чтобы позже добавить английский.

**Spotlight, Quick Note, перетаскивание, контекстные меню** из раздела 1 требований описаны в MAC-11, MAC-04, UI-06 и UI-07.

Приёмка: в String Catalog нет строк без русского перевода; в интерфейсе нет английских надписей, кроме названий форматов и технологий.

### 4.2 Редактор Markdown (раздел 2 требований)

**ED-01. Режимы: оформленный, исходник, разделённый · P0 (первые два), P1 (разделённый)**

- «Оформленный» (по умолчанию): разметка скрыта и видна только у элемента под курсором. Уже работает в текущем Пере.
- «Исходник»: весь Markdown моноширинным шрифтом. Уже работает, ⌘/.
- «Разделённый»: слева исходник, справа отрисованный вид (рендерер 5.7), прокрутка синхронная.

Приёмка: переключение не сдвигает строку с курсором с экрана; режим запоминается между запусками; переключение режима не меняет файл ни на байт.

**ED-02. Название — первая строка · P0**

Первая непустая строка — название заметки: в списке, в имени файла (R17), в заголовке окна. Она оформляется крупно (стиль «Название»), даже если перед ней нет `#`. Новая заметка начинается со стиля из настройки «Новые заметки начинаются с», по умолчанию `# `.

Приёмка: заметка без `#` в первой строке всё равно показывает её как название; пустая заметка в списке называется «Новая заметка»; если стереть весь текст, файл не переименовывается в пустое имя.

**ED-03. Синтаксис Markdown (CommonMark + GFM) · P0**

Заголовки H1–H6 (`#` и подчёркивание `===`/`---`), жирный, курсив, жирный курсив, зачёркнутый, инлайн-код, ссылки (обычные, ссылочные, автоссылки, голые адреса), картинки, списки маркированные и нумерованные любой вложенности, чек-листы, цитаты (в том числе вложенные), блоки кода с языком и с отступом, таблицы с выравниванием, горизонтальные линии, экранирование `\`. HTML внутри заметки показывается как текст, кроме разрешённых тегов (`<u>`, `<img>`, `<br>`, решение В7). Front matter в начале файла скрывается и показывается плашкой «Свойства». Сноски и формулы пока остаются текстом (P2, как в README сейчас).

Приёмка:
- Набор эталонных файлов (`examples/` и примеры из спецификации CommonMark) после открытия и сохранения без правок не меняется ни на байт (это уже проверяет `check.sh`).
- Снимки оформленного режима совпадают с эталонными снимками.
- Экспорт в HTML проходит тесты спецификации CommonMark (markdown-it их проходит).

**ED-04. Клавиши Notes, которые пишут Markdown · P0**

Полная таблица — в Приложении А. Главное: ⇧⌘T, ⇧⌘H, ⇧⌘J — `#`, `##`, `###`; ⇧⌘B — основной текст (снимает заголовок, список, цитату); ⇧⌘M — моноширинный; ⇧⌘7, ⇧⌘8, ⇧⌘9 — списки; ⇧⌘L — чек-лист; ⇧⌘U — отметить пункт; ⌘' — цитата; ⌘B, ⌘I, ⌘U, ⇧⌘X — `**`, `*`, `<u>`, `~~`; ⌘K — ссылка; ⌥⌘T — таблица; ⌘L — разделитель; ⌘] и ⌘[, Tab и ⇧Tab — уровень списка; ⌃⌘↑ и ⌃⌘↓ — переместить пункт.

Приёмка:
- Каждая команда работает как переключатель: повтор снимает форматирование (так уже устроен `format.js`).
- Команды работают на нескольких строках и при нескольких курсорах.
- Одна команда — один шаг отмены.
- Меню «Формат» показывает галочку у текущего стиля.

Конфликты с текущим Пером: ⌘1…⌘6 больше не задают заголовки (в Notes это вид списка, галерея и вложения); ⌘E возвращается системе («Использовать выделенное для поиска»); уровни H1–H6 доступны на ⌃⌘1…⌃⌘6 (дополнение Пера).

**ED-05. Чек-листы · P0**

- Щелчок по кружку переключает `[ ]` и `[x]` (уже работает; форма кружка — как в Notes).
- ↩ на пункте создаёт новый `- [ ] `, ↩ на пустом пункте выходит из списка, ⇧↩ переносит строку внутри пункта (в файле — жёсткий перенос `\` и отступ).
- Команды: «Отметить все», «Снять все отметки», «Переместить отмеченные вниз»; настройка «Автоматически сортировать отмеченные пункты».
- Пункты перетаскиваются мышью и переставляются ⌃⌘↑/↓.

Приёмка: переключение пункта меняет в файле ровно один символ; при сортировке подпункты переезжают вместе с родителем; отмена возвращает прежний порядок.

**ED-06. Списки · P0**

↩ продолжает список (номер +1), ↩ на пустом пункте выходит из него; Tab/⇧Tab и ⌘]/⌘[ меняют уровень, при этом отступ равен ширине маркера родителя, чтобы CommonMark правильно понял вложенность; ⇧⌘7/8/9 меняют тип списка с сохранением вложенности; нумерация пересчитывается после вставки и удаления пунктов (P1).

Приёмка: список, построенный клавишами, после экспорта в HTML имеет ту же вложенность, что на экране.

**ED-07. Ссылки · P0**

⌘K открывает окно «Добавить ссылку» (текст и адрес). Голые адреса становятся автоссылками. Ссылка на `.md` внутри библиотеки открывает заметку в Пере. `#якорь` прокручивает к заголовку. `mailto:` и `tel:` передаются системе, `javascript:` и `data:` блокируются (уже сделано). Что делает простой щелчок по ссылке, а что ⌘-щелчок, — по эталону Notes (сейчас в Пере ссылка открывается ⌘-щелчком).

Приёмка: ссылка на `.md` из библиотеки открывает заметку в Пере, а не файл в другом приложении; `#якорь` прокручивает к заголовку; ссылка `javascript:` не выполняется.

**ED-08. Картинки и их размер · P0 вставка, P1 размер**

- Вставка перетаскиванием, из буфера (⌘V), через «Прикрепить файл» (⇧⌘A) и Continuity Camera. Файл копируется в `Attachments/`, в текст пишется `![](Attachments/…)`.
- Картинка вписывается в ширину колонки. Режимы «Мелкие» и «Крупные» картинки задаются глобально, как в Notes.
- Размер меняется ручкой в углу; при отпускании разметка становится `<img src="…" width="N" alt="…">`. «Исходный размер» возвращает `![]()`.
- HEIC сохраняется как есть; при экспорте в HTML есть опция перевести его в JPEG.

Приёмка: фото 12 Мп показывается уменьшенным не позже чем через 300 мс после вставки; в файле записан относительный путь; удаление ссылки на картинку не удаляет файл сразу (STO-07).

**ED-09. Блоки кода с подсветкой · P0**

Уже работает для ~100 языков (Lezer). Нужно: подсказка имени языка после ```` ``` ```` (PRO-03); одинаковая подсветка в редакторе, экспорте и Quick Look (5.7).

Приёмка: подсветка не задерживает ввод (PERF-02).

**ED-10. Таблицы · P0 показ и вставка, P1 правка в сетке**

- Таблица показывается сеткой (уже работает). Сейчас щелчок по ячейке открывает исходник; в P1 ячейка правится прямо в сетке.
- ⌥⌘T вставляет таблицу 2×2.
- Клавиши Notes в таблице (Приложение А): Tab/⇧Tab — между ячейками, ↩ — строка ниже или новая строка в конце, ⌥↩ — перенос внутри ячейки (`<br>`), ⌥⌘↑/↓/←/→ — добавить строку или столбец, ⌘A ⌘A — вся таблица.
- Контекстное меню: добавить и удалить строку или столбец, переставить перетаскиванием, «Преобразовать в текст».
- При записи `|` в ячейке экранируется как `\|`. Столбцы выравниваются пробелами, только если таблица уже была выровнена: чужое форматирование не ломается.

Приёмка: каждая операция — один шаг отмены; таблица 50×10 правится без задержек; правка ячейки в невыровненной таблице меняет байты только своей строки.

**ED-11. Цитаты, разделители, сворачивание разделов · P0 / P1**

Цитаты и разделители — P0 (`>` и `---`, ⌘' и ⌘L). Сворачивание разделов (Notes 15) — P1: при наведении слева от заголовка появляется стрелка; раздел сворачивается до следующего заголовка того же или более высокого уровня; состояние хранится в индексе, а не в файле.

Приёмка: поиск и переход по ссылке на раздел разворачивают нужный раздел; свёрнутый раздел никак не меняет файл.

**ED-12. Автоформатирование при наборе · P0 базовое, P1 остальное**

- `- `, `* `, `1. `, `> `, `# ` в начале строки сразу оформляются (это обычный Markdown, уже работает).
- `[] ` в начале строки превращается в `- [ ] `; `---` и ↩ — в разделитель; ```` ``` ```` и ↩ — в блок кода с закрывающей оградой; строка вида `| a | b |` и ↩ — в таблицу со строкой-разделителем.
- Системные автозамены (кавычки-ёлочки, тире) работают по системным настройкам и никогда внутри кода и адресов ссылок.
- `>>` и `[[` открывают выбор заметки (PRO-04), `#` и буква — подсказку тегов (ORG-03).

Приёмка: любое автоформатирование отменяется одним ⌘Z и возвращает ровно набранные символы.

**ED-13. Оглавление из заголовков · P2**

Панель «Оглавление» (есть в текущем Пере: щелчок — переход, текущий заголовок подсвечен). Команда «Вставить оглавление» пишет список ссылок `[Заголовок](#якорь)` между `<!-- toc -->` и `<!-- /toc -->`; «Обновить оглавление» его перестраивает. Якоря строятся по правилам GitHub, кириллица сохраняется.

Приёмка: оглавление ведёт к нужным заголовкам в Пере, в экспортированном HTML и на GitHub.

**ED-14. Отмена и повтор · P0**

⌘Z и ⇧⌘Z. У каждой заметки своя история отмены, она сохраняется при уходе на другую заметку и возврате в течение сеанса.

Приёмка: после перехода на другую заметку и возврата ⌘Z отменяет последнюю правку этой заметки; форматирование и вставка вложения отменяются одним шагом.

### 4.3 Организация (раздел 3 требований)

**ORG-01. Папки и вложенные папки · P0**

Папка Пера — это каталог на диске. Создание (⇧⌘N), переименование, удаление, вложение перетаскиванием, перенос заметок. «Заметки» — корень библиотеки; «Быстрые заметки» — системная папка. Если имя занято, добавляется « 2».

Приёмка: папка, созданная в Finder внутри библиотеки, появляется в Пере не позже чем через 1 с; переименование папки в Пере не ломает картинки в её заметках (пути переписываются, 5.5.5).

**ORG-02. Смарт-папки · P1**

Фильтры как в Notes (точные значения каждого фильтра сверить с эталоном): теги (выбранные, любой тег, без тегов), дата создания, дата изменения (сегодня, вчера, последние 7 и 30 дней, до, после, диапазон), чек-листы (есть, все отмечены, есть неотмеченные), вложения (любые, фото, сканы, документы, рисунки, аудио), папки (включить или исключить), быстрые заметки, закреплённые, заблокированные. Фильтры «общие» и «упоминания» не нужны. Соответствие всем фильтрам или любому; хотя бы один фильтр обязателен.

«Преобразовать в смарт-папку» — как в Notes: заметки переносятся в «Заметки» и получают тег с именем папки; это необратимо и требует подтверждения; недоступно для папок с вложенными папками и заблокированными заметками.

Фильтр «по ключевому слову» из требований — в Notes его нет, он реализуется как сохранённый поиск (PRO-06, P2).

Приёмка: содержимое смарт-папки обновляется не позже чем через 1 с после правки заметки; на 10 000 заметок выборка занимает не больше 100 мс; описание смарт-папки хранится в `state.json`.

**ORG-03. Теги · P0 базовые, P1 браузер тегов, P2 цвета**

- Тег — `#слово` в тексте: буквы любого алфавита, цифры, `_`, `-`. Не тег: заголовок `# `, `#` внутри слова, внутри кода и адресов. Точные правила — по эталону Notes.
- Подсказка при наборе и подсветка в тексте.
- Браузер тегов в боковой панели: выбор одного или нескольких тегов фильтрует заметки, есть «Все теги».
- «Переименовать тег» правит все заметки; «Удалить тег» убирает `#тег` из текста, с подтверждением.
- Список `tags:` во front matter учитывается, но Перо его не пишет.
- Цвета тегов (P2, R1) хранятся в `state.json` и видны в браузере и в тексте.

Приёмка: переименование тега в 1 000 заметок выполняется одной операцией; если не удалось записать хотя бы один файл, все уже изменённые файлы возвращаются в исходное состояние.

**ORG-04. Закреплённые заметки · P0**

Закрепить и открепить можно из меню «Файл», контекстного меню, свайпом вправо двумя пальцами и перетаскиванием между разделами. Раздел «Закреплённые» стоит наверху каждой папки. В «Недавно удалённых» закреплять нельзя. Закрепления хранятся в `state.json` по относительному пути.

Приёмка: закрепление переживает перезапуск, переименование и перенос заметки внутри Пера.

**ORG-05. Недавно удалённые · P0**

Удалённая заметка хранится 30 дней, потом удаляется навсегда. Видно, сколько дней осталось. Восстановление: «Переместить в…» или «Восстановить» (в исходную папку, а если её нет — в «Заметки»). «Удалить навсегда» — с подтверждением. Удалённые заметки не попадают в поиск, смарт-папки, Spotlight и виджеты. Вложения, на которые ссылаются только удалённые заметки, уходят вместе с ними по истечении срока.

Приёмка: при подменённых часах заметка, удалённая 31 день назад, исчезает при ближайшей проверке (при запуске и раз в сутки); восстановленная заметка байт в байт совпадает с удалённой.

**ORG-06. Блокировка заметок · P1**

Интерфейс как в Notes: «Заблокировать заметку»; при первой блокировке — выбор пароля (пароль для входа в Mac или свой, с подсказкой) и Touch ID; поле ввода пароля на месте текста; после разблокировки все заблокированные заметки открыты до бездействия или выхода; кнопка с замком «Закрыть заблокированные заметки». Ограничения Notes сохраняются: нельзя заблокировать быструю заметку, заметку с тегами, заметку с аудио, видео, PDF или документами. Шифрование — SEC-02, Touch ID — SEC-03.

Приёмка: текст заблокированной заметки не виден без пароля или Touch ID ни в редакторе, ни в списке, поиске, Spotlight, виджетах и галерее; попытка заблокировать заметку с тегом или PDF показывает объяснение, как в Notes; после выхода из Пера заметки снова закрыты.

**ORG-07. Вид «Список» · P0**

UI-03 плюс сортировка по дате изменения, дате создания или названию, в обе стороны; своя сортировка для папки («Ещё ▸ Сортировать»); группировка по датам (Сегодня, Вчера, Предыдущие 7 дней, Предыдущие 30 дней, месяцы, годы) глобально и для папки; при сортировке по названию группировка скрыта. Щелчок по дате в строке переключает дату создания и изменения (из справки Apple).

Приёмка: сортировка и группировка каждой папки переживают перезапуск; закреплённые заметки стоят сверху при любой сортировке; «Все заметки» и «Недавно удалённые» всегда используют общую сортировку (как в Notes).

**ORG-08. Вид «Галерея» · P1**

⌘2 показывает карточки: миниатюра (первая картинка, скан или рисунок, иначе первые строки текста), название, дата. Закреплённые сверху, та же сортировка и группировка. ⌘1 возвращает список.

Приёмка: миниатюры строятся в фоне и кэшируются в `.pero/cache/`; 5 000 карточек прокручиваются без рывков.

**ORG-09. Просмотр вложений · P1**

⌘3 показывает все вложения библиотеки по категориям: фото и видео, сканы, документы, рисунки, аудио, ссылки. Категории «Карты» нет (R11). У каждого вложения есть «Показать в заметке».

Приёмка: «Показать в заметке» открывает заметку и прокручивает к вложению; вложения удалённых и заблокированных заметок в просмотре не показываются.

### 4.4 Основные функции (раздел 4 требований)

**CORE-01. Автосохранение · P0**

Кнопки «Сохранить» нет. Файл записывается не позже чем через 1 с после последнего нажатия клавиши, а также при переходе на другую заметку, уходе приложения в фон, выходе и сне. Запись атомарная (временный файл, затем замена), дата создания и права файла сохраняются, нетронутые байты не меняются.

Приёмка: процесс, убитый `kill -9` через 1,5 с после ввода, оставляет текст на диске; дата создания файла после 100 сохранений та же; `check.sh` подтверждает сохранение байт в байт.

**CORE-02. История версий · P2**

Снимки в `.pero/versions/`: не чаще раза в 5 минут непрерывной правки и при уходе из заметки. Хранение: все снимки за последние сутки, затем по одному в час на неделю, по одному в день на месяц, по одному в неделю на год; общий лимит места (по умолчанию 500 МБ, старые удаляются первыми). Окно «История версий»: список по времени, сравнение с текущим текстом с подсветкой различий, «Восстановить» (текущий текст сначала сохраняется снимком), «Скопировать». У заблокированных заметок версий нет.

Приёмка: восстановленный текст байт в байт равен снимку.

**CORE-03. Вложения · P0 картинки, PDF, файлы; P1 рисунки, сканы; P3 аудио**

Типы: изображения, PDF, любые документы (карточка со значком, пробел открывает Quick Look), сканы (PDF), рисунки (SVG), аудио (`.m4a`, P3). Файлы лежат в `Attachments/ГГГГ/ММ/<короткий-id>-<исходное имя>`, ссылка в заметке относительная. PDF показывается карточкой или встроенным просмотром (PDFKit), текст PDF индексируется для поиска. «Разметка» (Markup) — через системный Quick Look (P1).

Приёмка: исходный файл не меняется; тот же файл, вставленный повторно, не копируется второй раз (сравнение по хэшу).

**CORE-04. Рисунки · P1 через iPhone/iPad, P3 свой холст**

См. R5.

Приёмка: рисунок, сделанный на iPad через «Добавить рисунок», сохраняется во вложения и вставляется ссылкой в место курсора.

**CORE-05. Сканирование документов · P1**

«Файл ▸ Вставить с iPhone или iPad ▸ Сканировать документы / Сделать фото / Добавить рисунок». Результат — PDF или JPEG во вложениях и ссылка в месте курсора. Текст распознаётся в фоне (Vision, русский и английский) и попадает в индекс поиска, но не в файл.

Приёмка: при доступном iPhone пункт меню активен, когда фокус в редакторе; многостраничный скан сохраняется одним PDF; слово из скана находится поиском не позже чем через минуту после вставки.

**CORE-06. Таблицы с правкой · P0 / P1**

Описание и приёмка — в ED-10.

**CORE-07. Чек-листы и прогресс · P0 / P2**

ED-05, плюс индикатор «3 из 7» в строке состояния заметки (P2, R1).

Приёмка: индикатор (P2) пересчитывается при каждом переключении пункта и учитывает вложенные пункты.

**CORE-08. Поделиться и AirDrop · P1**

Системное меню «Поделиться» (`NSSharingServicePicker`): AirDrop, Почта, Сообщения и другие. Заметка без вложений передаётся файлом `.md`; с вложениями — на выбор PDF или архив с `.md` и папкой вложений. Кнопки «Совместная работа» нет.

Приёмка: заметка, переданная по AirDrop на iPhone, открывается в «Файлах» с картинками.

**CORE-09. Печать · P0**

⌘P открывает системную панель печати. Оформление как у экспорта в PDF: белая бумага в любой теме, размер бумаги из системы, картинки и таблицы на месте. Используется существующий механизм `PDFRenderer` с показом панели печати.

Приёмка: печать в PDF через панель печати даёт тот же результат, что экспорт в PDF (CORE-10): те же разрывы страниц, картинки и таблицы.

**CORE-10. Экспорт · P0 (PDF, HTML, MD), P1 (TXT, пакетный)**

- PDF — уже есть.
- HTML — уже есть; добавить опцию: картинки копируются в папку `<имя>_files/` или встраиваются в файл.
- MD — файл и его вложения, пути переписываются относительно нового места; опция «вики-ссылки в обычные ссылки» (R19).
- TXT — текст без разметки: заголовки отдельными строками, пункты списков с «•», чекбоксы «☐» и «☑», таблицы через табуляцию, ссылки как «текст (адрес)».
- Пакетный экспорт выбранных заметок, папки или всей библиотеки с сохранением структуры папок.

Приёмка: круговой тест — экспорт в MD и импорт в пустую библиотеку дают те же заметки и вложения байт в байт.

**CORE-11. Импорт · P0 / P1 / P3**

- Markdown, файлы и папки (P0): опция «Сохранять структуру папок», результат в папке «Импортированные заметки», как в Notes. Картинки по относительным путям копируются во вложения, пути переписываются.
- TXT, RTF, RTFD, HTML (P1, Notes это умеет): через `NSAttributedString` и конвертер в Markdown.
- ENEX из Evernote с тегами и вложениями (P1, Notes это умеет).
- Из Apple Notes (R2): через AppleScript (P0), через экспорт Notes 26+ (P0, это импорт папки Markdown), через `NoteStore.sqlite` (P3).
- После импорта — отчёт: сколько заметок, что потеряно (шрифты, цвета, неподдержанные вложения).

Приёмка: тестовый набор из 30 заметок со всеми видами форматирования, заготовленный в Notes на macOS 15, импортируется; каждый элемент совпадает с таблицей 1.5 или указан в отчёте как потеря.

**CORE-12. Копирование и вставка с форматированием · P0**

- ⌘C кладёт в буфер одновременно Markdown простым текстом, HTML и RTF. В TextEdit, Pages и почте вставится оформленный текст, в терминал и редактор кода — Markdown.
- «Скопировать как Markdown» (есть и в Notes 27) кладёт только текст.
- ⌘V: из Пера или простой текст вставляется как есть; HTML или RTF из браузера, Pages, Word конвертируется в Markdown (заголовки, начертания, ссылки, списки, таблицы, цитаты, код); картинки из буфера сохраняются во вложения; картинки по `http`-адресам остаются ссылками (R11).
- ⌥⇧⌘V «Вставить и согласовать стиль» вставляет простой текст.

Приёмка: заметка, скопированная из Пера и вставленная обратно, даёт тот же Markdown; набор фрагментов из Википедии, Google Docs, Pages и Notes конвертируется в ожидаемый Markdown.

**CORE-13. Найти и заменить · P0**

⌘F открывает панель поиска в заметке с заменой, учётом регистра, поиском слова целиком и регулярными выражениями (уже есть, на русском); ⌘G и ⇧⌘G — следующее и предыдущее совпадение. ⌥⌘F, как в Notes, — поиск по всем заметкам. В оформленном режиме совпадение внутри скрытой разметки раскрывает её.

Приёмка: «Заменить все» отменяется одним ⌘Z; ошибочное регулярное выражение не роняет поиск, а подсвечивается как ошибка; поиск по 10 000-строчной заметке укладывается в PERF-02.

**CORE-14. Счётчик слов и время чтения · P2**

Строка состояния: слова, символы с пробелами и без, время чтения (200 слов в минуту, с округлением вверх); для выделения отдельно. Строку можно скрыть: «Вид ▸ Строка состояния». Счётчик слов и символов уже есть.

Приёмка: на эталонных текстах число слов совпадает с ручным подсчётом; разметка (`**`, `#`, адреса ссылок, `[ ]`) словами не считается (так уже работает `stats.js`).

**CORE-15. Дублировать заметку · P1**

⌘D создаёт копию «Название 2» в той же папке. Вложения не копируются: копия ссылается на те же файлы.

Приёмка: копия открывается в редакторе, оригинал не меняется; удаление копии не трогает общие вложения, пока на них ссылается оригинал.

**CORE-16. Ссылки между заметками и навигация · P1**

PRO-04 плюс ⌥⌘] и ⌥⌘[ — вперёд и назад по переходам между заметками, как в Notes.

Приёмка: ⌥⌘[ после перехода по ссылке возвращает к исходной заметке и к месту, откуда был переход; ⌥⌘] повторяет переход.

### 4.5 Локальное хранение (раздел 5 требований)

**STO-01. Библиотека на диске · P0**

Устройство — в 5.5.

Приёмка: библиотеку можно закрыть, скопировать в другое место, открыть там и получить те же заметки, папки, закрепления и смарт-папки.

**STO-02. Индекс SQLite · P0**

FTS5, списки, теги, ссылки, задачи (5.5.4). Пункт «Перестроить индекс» спрятан в меню «Справка».

Приёмка: удаление `.pero/cache/` и перезапуск восстанавливают всё, кроме свёрнутых разделов и распознанного текста, который распознаётся заново в фоне.

**STO-03. Изменения снаружи · P0**

Изменения из Finder, git и других редакторов видны в Пере не позже чем через 1 с (FSEvents). Открытая заметка без несохранённых правок обновляется на месте, как сейчас. Если заметку одновременно правили в Пере и снаружи, файл на диске остаётся внешним, а текст из Пера сохраняется рядом как «Название (конфликт ДД.ММ ЧЧ-ММ).md», и об этом показывается сообщение.

Приёмка: `git checkout` другой ветки с изменением 500 файлов отражается в списке без зависания интерфейса.

**STO-04. Резервная копия в iCloud Drive · P1**

По расписанию (раз в день или в неделю) и вручную. Копия — архив `Перо ГГГГ-ММ-ДД.zip` в выбранной папке (по умолчанию «iCloud Drive/Перо — резервные копии»; в песочнице папка выбирается в окне выбора и запоминается закладкой). Хранятся последние 10 копий. «Восстановить из резервной копии…» — в новую библиотеку или поверх текущей, с подтверждением. Заблокированные заметки остаются зашифрованными. Держать саму библиотеку в iCloud Drive можно, но это не поддерживаемая синхронизация: при правке с двух Маков возможны конфликты.

Приёмка: восстановление из копии даёт ту же библиотеку байт в байт.

**STO-05. Экспорт и импорт всей библиотеки вручную · P0**

«Экспортировать библиотеку…» сохраняет папку или архив; импорт — CORE-11.

Приёмка: экспорт всей библиотеки и импорт его в пустую библиотеку дают те же заметки, папки и вложения (как круговой тест CORE-10).

**STO-06. Без аккаунта, полностью офлайн · P0**

Приёмка: первый запуск не требует регистрации; при выключенной сети ни одно действие не выдаёт ошибок и предупреждений.

**STO-07. Уборка вложений · P1**

Вложение без ссылок (с учётом корзины и истории версий) удаляется через 30 дней после того, как пропала последняя ссылка на него.

Приёмка: вложение, на которое ссылается только удалённая заметка или снимок истории, не удаляется, пока они существуют.

**STO-08. Место хранения · P0**

По умолчанию `Application Support/Pero` (с учётом песочницы, R12). В настройках можно выбрать другую папку и перенести библиотеку.

Приёмка: после переноса библиотеки в другую папку на месте все заметки, вложения, закрепления и смарт-папки; старая папка удаляется только после подтверждения.

### 4.6 Возможности macOS (раздел 6 требований)

**MAC-01. Нативное приложение · P0**

Swift, AppKit и SwiftUI. Описание и приёмка — в TECH-01…TECH-03.

**MAC-02. Главное меню · P0**

Меню как в Notes: Перо, Файл, Правка, Формат, Вид, Окно, Справка. Все команды из Приложения А есть в меню. Значок в строке меню (`NSStatusItem`) с «Новая быстрая заметка» и «Поиск» — P2 (R1).

Приёмка: у каждой команды из Приложения А есть пункт меню с тем же сочетанием; неуместные в текущем контексте пункты неактивны, а не скрыты.

**MAC-03. Число на значке в Dock · P2**

`NSApp.dockTile.badgeLabel`. Что считать, выбирается в настройках (например, заметки в «Быстрых заметках»); по умолчанию выключено.

Приёмка: число на значке совпадает с выбранным счётчиком и обновляется не позже чем через 1 с после изменения.

**MAC-04. Быстрая заметка · P1**

Панель (`NSPanel`) поверх всех окон, на всех рабочих столах и поверх полноэкранных приложений. Создаёт заметку в «Быстрых заметках». Учитывает настройку «Всегда продолжать последнюю быструю заметку». Вызывается своим глобальным сочетанием (`RegisterEventHotKey`, права «Универсального доступа» не нужны), из «Служб» и из расширения «Поделиться». Fn‑Q и горячий угол — нет (R8).

Приёмка: из любого приложения, в том числе полноэкранного, сочетание открывает панель не позже чем через 300 мс, когда Перо запущено; заметка сохраняется, даже если панель закрыли сразу после ввода.

**MAC-05. Центр уведомлений · по решению**

Notes присылает уведомления только об общих заметках, а они исключены. Виджеты в Центре уведомлений — MAC-08. Предложение: уведомлять только о завершении долгих операций (импорт, экспорт, резервная копия), если Перо в этот момент в фоне. Решить (В13).

Приёмка (если предложение принято): уведомление приходит, только когда Перо не активно, и щелчок по нему открывает результат операции.

**MAC-06. Handoff · P3**

См. R4. Приёмка — после решения В4.

**MAC-07. Siri и «Команды» (App Intents) · P1**

Действия: «Создать заметку» (название, текст, папка), «Добавить к заметке», «Открыть заметку», «Найти заметки» (с фильтрами, возвращает заметки), «Получить текст заметки» (Markdown), «Показать папку», «Переместить заметку», «Закрепить или открепить», «Добавить тег», «Удалить заметки», «Экспортировать заметку» (возвращает файл). Фразы для Siri на русском, например «Создай заметку в Пере».

Приёмка: действия видны в приложении «Команды» с русскими названиями; «Создать заметку» и «Добавить к заметке» работают без открытия окна Пера.

**MAC-08. Виджеты · P1**

«Заметка» (начало выбранной заметки), «Папка» (последние заметки папки), «Закреплённые»; маленький, средний и большой размер; на рабочем столе и в Центре уведомлений. Щелчок открывает заметку в Пере (`pero://note/…`). Заблокированная заметка показывается замком.

Приёмка: правка заметки видна в виджете не позже чем через минуту (частоту обновления ограничивает система); виджет работает, когда Перо не запущено.

**MAC-09. Расширение «Поделиться» · P1**

Из Safari (адрес, название страницы, выделенный текст), «Фото», Finder и любых приложений с текстом. Варианты: «Новая заметка», «Добавить к заметке…», выбор папки, «В быструю заметку».

Приёмка: страница из Safari, отправленная при закрытом Пере, оказывается в нужной папке при следующем запуске; при открытом Пере — не позже чем через 2 с.

**MAC-10. Quick Look для `.md` · P2**

Расширение предпросмотра: любой `.md` в Finder по пробелу показывается оформленным, как в экспорте — заголовки, списки, чекбоксы, таблицы, подсветка кода, светлая и тёмная тема. Картинки рядом с файлом показываются, если расширению хватает доступа (проверить в спайке), иначе — подпись. Миниатюры в Finder (`QLThumbnailProvider`) — P3.

Приёмка: пробел на `examples/Пример.md` в Finder показывает оформленный документ не позже чем через 1 с, Перо при этом не запускается.

**MAC-11. Spotlight · P1**

Core Spotlight: каждая заметка — отдельный элемент (название, текст без разметки, теги как ключевые слова, папка, даты, миниатюра). Выбор результата открывает заметку в Пере. Удалённые заметки убираются из Spotlight, у заблокированных индексируется только название. Заметки также отдаются системе как сущности App Intents (`IndexedEntity`), чтобы Spotlight в macOS 26+ мог выполнять над ними действия. Если библиотека лежит в `~/Documents`, система проиндексирует и сами `.md`-файлы, возможны дубли; это допустимо, это файлы пользователя.

Приёмка: заметка, созданная в Пере, находится в Spotlight не позже чем через 1 минуту.

**MAC-12. Полное управление с клавиатуры · P0**

Tab переключает боковую панель, список и поиск; ↩ переводит в редактор; выход из редактора в список — по эталону Notes; все команды есть в меню с сочетаниями; работает с включённым «Полным доступом с клавиатуры», фокус всегда виден.

Приёмка: сценарий «создать папку, заметку, отформатировать, закрепить, переместить, удалить, восстановить» выполняется без мыши.

**MAC-13. VoiceOver · P1**

Подписи у всех элементов. Строка списка читается как «Название, дата, начало текста, закреплена». В редакторе заголовки объявляются с уровнем, чекбоксы — как флажки с состоянием, ссылки — как ссылки; ротор переходит по заголовкам; у строк списка есть действия «Закрепить» и «Удалить». В оформленном режиме скрытая разметка не зачитывается (самое сложное место, R14).

Приёмка: Accessibility Inspector не находит элементов без подписи; сценарий MAC-12 проходится с VoiceOver.

**MAC-14. Жесты трекпада · P1**

Свайп двумя пальцами по строке списка: вправо — «Закрепить», влево — «Удалить» и «Поделиться», как в Notes. Сильное нажатие — системный просмотр ссылок и вложений. Свайп назад и вперёд по переходам между заметками — P2.

Приёмка: свайп по строке открывает кнопки действий, как в Notes; действие выполняется щелчком по кнопке и отменяется ⌘Z.

**MAC-15. Службы · P2**

Пункт «Новая заметка Пера из выделенного» в меню «Службы» любого приложения.

Приёмка: текст, выделенный в Safari, через «Службы» становится новой заметкой в папке «Заметки».

**MAC-16. Системные возможности текста · P1**

Проверка правописания и грамматики, автозамены, диктовка, Writing Tools (по решению В8). При работе Writing Tools возвращает простой текст (`allowedWritingToolsResultOptions = .plainText`), иначе он вставит rich text, которого в Markdown нет.

Приёмка: правописание подчёркивает ошибки в тексте, но не в коде и адресах ссылок; после Writing Tools в заметке только Markdown, без rich text.

### 4.8 Уникальные функции Пера (раздел 8 требований)

**PRO-01. Оформленный вид без видимой разметки · P0**

Уже работает (`livepreview.js`), нужно распространить на новые элементы. Разметка видна только у элемента под курсором и подсвечена, как сейчас.

Приёмка: в оформленном режиме вне курсора не видно ни одного символа разметки; ← и → проходят оформленное слово по одному видимому символу за нажатие, без «застревания» на скрытых символах.

**PRO-02. Переключатель «исходник/оформление» одним щелчком · P0**

Кнопка на панели инструментов (есть) и ⌘/. Требования ED-01.

Приёмка — в ED-01.

**PRO-03. Умные подсказки Markdown · P2**

Подсказки по правилам, без ИИ и сети: автодополнение названий заметок после `[[` и `>>` и разделов после `#`; тегов; языков после ```` ``` ````. Ссылка, вставленная на выделенный текст, становится `[текст](адрес)`. Табличные данные из Numbers или Excel предлагается вставить как таблицу Markdown.

Приёмка: каждая подсказка отключается в настройках; Esc закрывает подсказку; текст меняется только после явного выбора (Tab или ↩).

**PRO-04. Вики-ссылки `[[ ]]` · P1**

Формы: `[[Название]]`, `[[Название|текст ссылки]]`, `[[Название#Раздел]]`. Вставка через `[[` и `>>`. Щелчок открывает заметку. При переименовании заметки ссылки обновляются во всех заметках (R17). Если названия совпадают, используется путь: `[[Папка/Название]]`. Ссылка на несуществующую заметку показывается серым, щелчок создаёт заметку (P2).

Приёмка: переименование заметки, на которую ссылаются 100 заметок, обновляет все ссылки и показывает, сколько заметок изменено.

**PRO-05. Панель обратных ссылок · P2**

Боковая панель справа: заметки, которые ссылаются на текущую, с фрагментом текста вокруг ссылки; щелчок ведёт к месту ссылки.

Приёмка: новая ссылка появляется в панели не позже чем через 1 с.

**PRO-06. Расширенный поиск с синтаксисом · P2**

Операторы: `tag:` или `#тег`, `in:Папка`, `has:checklist|image|pdf|table|code|link|attachment`, `is:pinned|locked|quick`, `todo:open|done`, `created:` и `edited:` (`>`, `<`, диапазон `..`, слова «сегодня», «вчера», `7d`), `"точная фраза"`, `-исключить`, `OR`, `title:`, `heading:` (только в заголовках), `code:` (только в коде), `link:[[Название]]`. Поиск можно сохранить как смарт-папку. Буква «ё» ищется и как «е».

Приёмка: у каждого оператора есть тест на тестовой библиотеке; запрос с ошибкой не падает, а ищется как обычный текст.

**PRO-07. Шаблоны папок · P2**

Шаблоны — обычные `.md` в `.pero/templates/`, редактируются в Пере («Настройки ▸ Шаблоны»). У папки может быть шаблон по умолчанию: новая заметка в ней начинается с него. Переменные `{{дата}}`, `{{время}}`, `{{папка}}`, `{{курсор}}`.

Приёмка: новая заметка в папке с шаблоном содержит шаблон с подставленными значениями, курсор стоит на месте `{{курсор}}`.

**PRO-08. Пакетные операции · P1 как в Notes, P2 сверх**

Для нескольких выбранных заметок: переместить, удалить, закрепить или открепить, экспортировать (как в Notes); добавить или убрать тег (P2).

Приёмка: операция над 1 000 заметками занимает не больше 5 с и показывает прогресс; перемещение, удаление и изменение тегов отменяются ⌘Z.

### 4.10 Приватность и безопасность (раздел 10 требований)

**SEC-01. Все данные локально · P0**

Описание и приёмка — в STO-01 и STO-06.

**SEC-02. Шифрование заметок · P1**

- Алгоритм: AES-256-GCM (CryptoKit).
- Ключ пароля: PBKDF2-HMAC-SHA256 (CommonCrypto), не меньше 600 000 итераций, соль 16 байт.
- У каждой заметки свой случайный ключ, обёрнутый ключом пароля. Смена пароля переобёртывает ключи, не перешифровывая содержимое.
- Файл заблокированной заметки — конверт `Название.pero-locked` (JSON): версия формата, параметры KDF, обёрнутый ключ, nonce, шифротекст. Название хранится открыто, как в Notes. Внутри шифротекста — Markdown и вложения заметки.
- Описание формата и короткий скрипт расшифровки без Пера лежат в репозитории (`docs/locked-format.md`), чтобы данные не зависели от приложения.
- При блокировке открытая версия удаляется из файлов, индекса, Spotlight, кэша миниатюр и истории версий; показывается предупреждение о копиях в git и резервных копиях (R16).

Приёмка: в файле `.pero-locked`, индексе и кэше нет ни одного слова из текста заметки, кроме названия; расшифровка скриптом из `docs/` даёт исходный Markdown.

**SEC-03. Touch ID · P1**

LocalAuthentication. Ключ хранится в Связке ключей с ограничением доступа: `.biometryCurrentSet` для Touch ID или `.userPresence` для режима «пароль для входа в Mac». После смены отпечатков нужен пароль. Автоблокировка через несколько минут бездействия (значение сверить с эталоном), при выходе, сне и блокировке экрана. Face ID на Mac нет (R7). Для Связки ключей с такими ограничениями могут понадобиться права подписи, проверить в спайке (R12).

Приёмка: после сна Мака заблокированная заметка снова закрыта; новый отпечаток не открывает заметку без пароля.

**SEC-04. Ни одного сетевого запроса · P0**

Приложение работает в песочнице без прав `com.apple.security.network.client` и `network.server`, поэтому система сама не даст ему выйти в сеть. Редактор грузит только `pero://`; правило `WKContentRuleList` дополнительно запрещает `http` и `https`. Удалённые картинки не загружаются (R11). Ссылки по щелчку пользователя открывает браузер.

Приёмка: в правах подписи нет сетевых прав; за час работы, включая заметку с `![](https://…)`, `nettop` не видит ни одного соединения от Пера.

**SEC-05. Без телеметрии · P0**

Никаких библиотек аналитики и сбора сбоев. Отчёты о сбоях — только системные отчёты Apple, по согласию в Системных настройках.

Приёмка: в собранном приложении нет сторонних библиотек аналитики и сбора сбоев (проверка по `otool -L` и `third-party-licenses.txt`).

**SEC-06. Открытый исходный код · по решению В12**

Публичный репозиторий, лицензия, воспроизводимая сборка, `third-party-licenses.txt` (уже генерируется `web/build.mjs`), `SECURITY.md`.

Приёмка (после решения В12): по инструкции в README приложение собирается из публичного репозитория на чистом Маке.

**SEC-07. Разрешения · P0**

Каждое запрашивается при первом использовании, с понятным объяснением в `Info.plist`: «Автоматизация» для Notes (только при импорте), микрофон (аудио, P3). «Полный доступ к диску» не нужен; он понадобится только для импорта из `NoteStore.sqlite` (P3).

Приёмка: при обычной работе (без импорта из Notes и без аудио) Перо не запрашивает ни одного разрешения.

#### 5.5.2 Имена файлов

- Имя — название заметки, очищенное: `/` и `:` заменяются на «-», пробелы по краям убираются, длина ограничена так, чтобы имя занимало не больше 255 байт UTF‑8 (около 120 русских букв).
- Если имя занято, добавляется « 2», « 3» и так далее.
- Переименование файла происходит после 2 с без ввода и при уходе из заметки, не на каждое нажатие клавиши (R17).
- Пустая заметка называется «Новая заметка.md».

#### 5.5.3 Запись

- Запись атомарная: временный файл в той же папке, затем `FileManager.replaceItemAt`. Дата создания и права исходного файла сохраняются (это проверяется тестом).
- Кодировка, BOM и переводы строк сохраняются, как сейчас в `MarkdownDocument`.
- Индекс обновляется после записи, а не вместо неё: даже если индекс сломан, текст на диске.

#### 5.5.4 Индекс

```sql

  thumbnail TEXT
);
CREATE TABLE tag (name TEXT PRIMARY KEY, display TEXT NOT NULL);
CREATE TABLE note_tag (note_id TEXT NOT NULL, tag TEXT NOT NULL, PRIMARY KEY (note_id, tag));
CREATE TABLE heading (note_id TEXT NOT NULL, level INTEGER, text TEXT, offset INTEGER);
CREATE TABLE link (source_id TEXT NOT NULL, target_title TEXT, target_id TEXT, section TEXT, offset INTEGER);
```

Перед записью в FTS текст приводится к нижнему регистру и «ё» заменяется на «е»: `remove_diacritics` в SQLite работает только для латиницы. Русской морфологии в FTS5 нет, поэтому поиск префиксный: «замет» находит «заметка» и «заметки» (так ищет и Notes).

#### 5.5.5 Сверка с диском и внешние изменения

- При запуске индекс открывается сразу, а сверка с диском (путь, размер, время изменения, идентификатор документа) идёт в фоне.
- FSEvents с событиями на уровне файлов. Переименование снаружи распознаётся по идентификатору документа APFS, поэтому закрепления и ID заметки сохраняются.
- Изменённый файл переразбирается, индекс обновляется.
- Открытая заметка без несохранённых правок обновляется на месте (сохраняются курсор и прокрутка, так уже делает `patch()` в `main.js`). Конфликт — STO-03.
- Перо само переписывает относительные пути к вложениям, когда переносит заметку в другую папку. При переносе файла снаружи пути не трогаются, а битые ссылки на картинки показываются заглушкой с командой «Найти вложение».

#### 5.5.6 Корзина, история, уборка

- Удаление переносит файл в `.pero/trash/<uuid>/` и пишет в `manifest.json` исходный путь и время. Ежедневная проверка удаляет то, что старше 30 дней.
- Снимки истории — `.pero/versions/<uuid заметки>/<ISO-время>.md` и `manifest.json` с путём заметки, чтобы история не терялась при пересборке индекса. Одинаковые снимки не дублируются.
- Уборка вложений — STO-07.

### 5.6 Редактор

#### 5.6.1 Протокол

```swift
    func viewState() -> EditorViewState              // курсор, выделение, прокрутка, история отмены
    func perform(_ command: EditorCommand)           // формат, списки, таблицы, вставка вложения…
```

Правки идут так же, как сейчас: редактор отдаёт список изменений, `NoteBuffer` их применяет, ядро сохраняет и индексирует. Оба движка проходят один и тот же приёмочный набор.

#### 5.6.2 `WebEditorEngine` (CodeMirror) — для MVP

Что меняется относительно текущего кода:
- Один `WKWebView` на окно на всё время работы; он создаётся при запуске параллельно с чтением индекса. Переключение заметки — `pero.load(text)`, без перезагрузки страницы.
- Кэш состояний (`EditorState`) последних ~20 заметок в странице, чтобы при возврате сохранялись история отмены и прокрутка.
- Новые элементы оформления: стиль названия, список с тире, `==`, `<u>`, `[[ ]]`, теги, карточки вложений, размер картинок, сворачивание разделов (в CodeMirror есть штатный механизм сворачивания).
- Все команды меню «Формат» и клавиши Notes (ED-04).
- Перетаскивание файлов, вставка картинок и Continuity Camera принимаются на нативной стороне: файл сохраняется во вложения, в страницу передаётся Markdown для вставки.
- Подписи и роли для VoiceOver у виджетов (чекбоксы, картинки, таблицы).
- `pero://file/` даёт доступ только к библиотеке и к папке открытого внешнего файла.

#### 5.6.3 `TextKitEditorEngine` (TextKit 2) — целевой

- **Вид.** `NSTextView(usingTextLayoutManager: true)`. Свойство `layoutManager` нигде не используется и `NSTextTable` не применяется, иначе вид откатится на TextKit 1; в отладочной сборке это проверяется: `textLayoutManager` не должен становиться `nil`.
- **Текст.** В `NSTextContentStorage` лежит ровно Markdown-текст файла. Все атрибуты нужны только для показа и не сохраняются, в файл пишется `string`.
- **Разбор.** Полный разбор swift-markdown в фоне после паузы около 50 мс; мгновенная подсветка изменённого абзаца лёгким построчным разбором, чтобы ввод не ждал полного разбора. Для 10 000 строк полный разбор cmark занимает единицы миллисекунд (проверить в спайке).
- **Оформление.** Через делегат `NSTextContentStorageDelegate.textContentStorage(_:textParagraphWith:)`: абзац получает шрифты и цвета только когда попадает в видимую область. Это и даёт масштабирование на большие заметки. Результаты кэшируются по содержимому абзаца и признаку «курсор внутри».
- **Скрытая разметка.** Символы разметки вне блока с курсором получают почти нулевой шрифт и прозрачный цвет. Курсор перепрыгивает скрытые диапазоны: выделение поправляется в `textView(_:willChangeSelectionFromCharacterRanges:toCharacterRanges:)`. Когда курсор входит в блок, блок перерисовывается с видимой разметкой. Копирование берёт исходный Markdown.
- **Блочные элементы.** Маркеры списков, кружки чек-листов, полосы цитат, фон блоков кода, линии рисуют собственные фрагменты раскладки (`NSTextLayoutManagerDelegate.textLayoutManager(_:textLayoutFragmentFor:in:)`). Щелчок по кружку переключает `[ ]` и `[x]`.
- **Картинки, PDF, рисунки.** Строка-ссылка скрывается, абзацу задаётся отступ высотой с картинку, фрагмент рисует уменьшенную картинку в этом месте. Символы вложений (`U+FFFC`) в текст не вставляются, иначе файл перестанет быть чистым Markdown.
- **Таблицы.** Строки таблицы скрываются, поверх их фрагментов кладётся вид-сетка (подвиды размещаются после раскладки видимой области). Правка ячейки идёт в поле поверх ячейки и заменяет в тексте только её диапазон. В MVP этого движка допустим вариант «щелчок открывает исходник», как в CodeMirror сейчас.
- **Сворачивание разделов.** Через `NSTextContentManagerDelegate.textContentManager(_:shouldEnumerate:options:)`: абзацы свёрнутого раздела просто не выдаются в раскладку.
- **Подсветка кода.** Lezer и `@lezer/highlight` из `export.js` в JavaScriptCore, в фоне, с кэшем по содержимому блока. Тогда подсветка одинакова в редакторе, экспорте и Quick Look.
- **Ввод.** Продолжение списков, автоформатирование, подсказки — в `shouldChangeText` и командах; каждое — отдельный шаг отмены.
- **Бесплатно от системы:** правописание, автозамены, диктовка, «Службы», Writing Tools (с `allowedWritingToolsResultOptions = .plainText`), поиск `NSTextFinder`, Continuity Camera (с перехватом, R6).
- **Доступность.** Отдельное представление текста без разметки для VoiceOver и элементы доступности для чекбоксов, картинок и таблиц — самая рискованная часть (R14).

#### 5.6.4 Спайк TextKit 2: условия перехода

Прототип на 2–3 недели. TextKit 2 заменяет CodeMirror, только если выполнено всё:

1. Заметка на 10 000 строк: открытие ≤ 300 мс, прокрутка без подвисаний, задержка ввода p95 ≤ 16 мс (PERF-02).
2. Курсор и выделение проходят через скрытую разметку без застреваний и без потери символов; работают ввод с композицией (японская раскладка) и диакритика.
3. Таблица 20×5 показывается сеткой и правится в ячейке без отката на TextKit 1.
4. VoiceOver читает оформленный абзац без символов разметки.
5. Весь приёмочный набор редактора (ED-01…ED-14, PRO-01) проходит на обоих движках одинаково.

Если хотя бы одно не выполнено, Перо остаётся на CodeMirror, а спайк повторяется на следующей версии macOS.

### 5.7 Отрисовка вне редактора

- **HTML.** Один рендерер — markdown-it и подсветка Lezer из `export.js`, собранные в отдельный файл для JavaScriptCore (без DOM и без процесса WebContent). Он нужен для экспорта в HTML, для PDF и печати (HTML затем раскладывается в скрытом `WKWebView`, как сейчас), для правой части разделённого режима и для Quick Look.
- **Текст без разметки** для индекса, Spotlight, TXT-экспорта и превью в списке собирается на Swift из разбора swift-markdown.
- **Виджеты** показывают название и начало текста без разметки: HTML в виджетах не отрисовать.

### 5.8 Расширения и связь с системой

**Quick Look (`PeroQuickLook`).** Расширение предпросмотра на данных: получает файл, отрисовывает HTML рендерером 5.7, возвращает `QLPreviewReply` с HTML и картинками как вложениями ответа. Старые генераторы `.qlgenerator` в macOS 15 больше не работают, поэтому только расширение. Риск: доступ к картинкам рядом с файлом (R12), проверить в спайке.

**«Поделиться» (`PeroShare`).** Окно с выбором «Новая заметка», «Добавить к заметке…», «В быструю заметку» и папки. Полученное записывается в `inbox/` контейнера App Group (JSON и файлы). Приложение забирает входящие при запуске и, пока работает, следит за папкой через FSEvents. Само расширение в библиотеку не пишет, чтобы писатель был один.

**Виджеты (`PeroWidgets`).** Приложение после изменений (не чаще раза в несколько секунд) пишет в App Group `widgets/snapshot.json` (заметки, папки, закреплённые, начало текста) и уменьшенные картинки, затем вызывает `WidgetCenter.reloadTimelines`. Настройка виджета (какая заметка, какая папка) — через `AppIntentConfiguration` с запросом заметок из снимка. Щелчок — `pero://note/<id>`, а если ID не найден — по пути.

**Spotlight (`SpotlightIndexer`).** `CSSearchableIndex` в приложении; элементы обновляются вместе с индексом; открытие результата приходит как `NSUserActivity` с `CSSearchableItemActionType`.

**App Intents (`Intents`).** Действия из MAC-07 работают в процессе приложения через `PeroKit`. `AppShortcutsProvider` с русскими фразами для Siri. Метаданные App Intents собирает только Xcode, это одна из причин TECH-09.

**Быстрая заметка.** Глобальное сочетание через `RegisterEventHotKey`; запуск при входе в систему через `SMAppService`.

**Continuity Camera.** Пункт «Файл ▸ Вставить с iPhone или iPad» с `NSMenuItem.importFromDeviceIdentifier`; редактор отвечает на `validRequestor(forSendType:returnType:)` для картинок и PDF и принимает данные в `readSelection(from:)` (R6).

**URL-схема.** `pero://note/<id>`, `pero://note?path=…`, `pero://new?folder=…&text=…`. Схема `pero://` уже используется внутри редактора для страницы (`pero://app/`), внешние адреса не должны с ней пересекаться: внутренние пути остаются в `WKURLSchemeHandler`, внешние обрабатывает приложение.

### 5.9 Безопасность

Конверт заблокированной заметки:

```json
{
  "format": "pero-locked",
  "version": 1,
  "title": "Пароли",
  "kdf": { "name": "PBKDF2-HMAC-SHA256", "iterations": 600000, "salt": "base64…" },
  "wrappedKey": "base64…",
  "cipher": "AES-256-GCM",
  "nonce": "base64…",
  "ciphertext": "base64…"
}
```

Внутри шифротекста — архив с `note.md` и вложениями заметки. Ключ-обёртка в Связке ключей защищён `.biometryCurrentSet` (Touch ID) или `.userPresence` (пароль для входа в Mac). Расшифрованное содержимое живёт только в памяти, на диск в открытом виде не попадает: ни в кэш, ни в индекс, ни в историю.

### 5.10 Сборка, подпись, раздача

- Проект Xcode; `run.sh` вызывает `xcodebuild` и, как сейчас, запускает собранное приложение.
- Права приложения: песочница, App Group, чтение и запись файлов, выбранных пользователем, закладки на эти файлы, Apple Events для `com.apple.Notes` (импорт). Сетевых прав нет.
- Права расширений: песочница, App Group.
- Для себя — подпись сертификатом Apple Development. Для раздачи — Developer ID и нотаризация (нужна платная программа разработчика, R12).
- Bundle id остаётся `local.pero.markdown` (R21).

### 5.11 Тестирование и приёмка

- **Модульные тесты** `PeroKit`: запись байт в байт (все кодировки и переводы строк), имена файлов, разбор (название, теги, ссылки, задачи), поиск и нормализация, смарт-папки, корзина с подменёнными часами, конверт шифрования.
- **Тестовый корпус:** `examples/`, примеры спецификации CommonMark, реальные файлы автора (`tools/check.sh ~/путь/к/*.md`), 30 эталонных заметок из Notes, библиотека на 10 000 заметок от `tools/make-library`.
- **Сценарные проверки:** `TestHooks` и `check.sh` развиваются в набор сценариев (создать, отформатировать, закрепить, перенести, удалить, восстановить, экспортировать, импортировать), которые прогоняются на обоих движках редактора.
- **Снимки экрана:** эталонные снимки оформленного режима, светлая и тёмная тема.
- **Скорость:** `tools/perf.sh` (PERF-08).
- **Доступность:** Accessibility Inspector и ручной проход с VoiceOver на каждый этап.
- **Сравнение с Notes:** снимки и видео бок о бок по списку экранов (R9).
